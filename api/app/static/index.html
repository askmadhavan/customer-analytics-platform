    Step 2 of 8 · Explore the raw data

    Before cleaning, find out what is wrong

    The raw tables are loaded, but are they ready for decisions? Ask them simple questions and the problems from the slide appear in real data: a duplicate, missing values, and inconsistent formats. Customers appear only as random codes, never names.

    How many orders?

    SELECT COUNT(*) FROM olist_orders_dataset;
    →99,441 orders

    How many customers does this shop have? Duplicate

    SELECT COUNT(customer_id) AS customer_ids, COUNT(DISTINCT customer_unique_id) AS real_people FROM olist_customers_dataset;
    →99,441 IDs vs 96,096 real people

    The marketplace gives the same person a new customer ID for every order. Count the wrong column and every churn number is wrong. This is Customer 101 appearing twice, in real life.

    Missing values: orders never delivered Missing

    SELECT COUNT(*) - COUNT(order_delivered_customer_date) FROM olist_orders_dataset;
    →2,965 orders with no delivery date

    Some are legitimate (a cancelled order is never delivered). Others are genuine gaps. Cleaning means deciding which is which.

    The churn rule. Reference date: 1 June 2018. A customer who has not bought anything in the 120 days before that date has churned (churn = 1).

    How many times did each person buy?

    SELECT frequency, COUNT(*) FROM mart_customer_rfm GROUP BY frequency ORDER BY frequency;

    97.0% of 75,387 customers bought exactly once. This shop's problem is not attracting customers. It is that they never come back.

    Churn rate: the slide said 10%

    SELECT ROUND(AVG(churn) * 100, 1) FROM mart_customer_rfm;

    48,804 of 75,387 customers churned. For a marketplace where most people buy once, that is normal. Remember this number in step 6.

    Step 5 of 8 · Choose features, split, train

    Practice on 60,309 customers. Keep 15,078 for the exam.

    A Random Forest studies past customers whose answer is known (churned or stayed), the way a student studies ten years of past papers. This is supervised classification.

    Features: what the model is allowed to see

    frequency monetary avg_order_value customer_lifetime_days recency churn (target)
    Why leave out recency? The churn label is "recency over 120 days". In all 75,387 rows, recency > 120 matches churn = 1 exactly. Give the model recency and it simply rediscovers our own rule: about 99.8% accuracy, and nothing learned. That is data leakage: printing the answer key inside the question paper.

    The 80/20 split: test_size=0.2

    Practice · 60,309
    Exam · 15,078

    The exam customers stay hidden while the model learns. A model that only does well on its practice data has memorised, not learned: overfitting.

    The model

    A Random Forest with 200 trees. Each tree asks yes-or-no questions such as "did this customer spend more than R$ 150?", then all 200 trees vote. class_weight="balanced" stops the majority class from drowning out the rest.
